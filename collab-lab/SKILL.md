# 协作实验台 (collab-lab)

## 这个 skill 解决什么

`experiment-standards` 的产出物是**给机器复现用的**：`run_manifest.json`、`events.jsonl`、
`predictions/*.npy`、`training/*_metrics.csv`、`evaluation_report.json`。它们的设计目标是
"以后能重算"，不是"人能读懂"。

`bayes-dl-dcu` 的协议是**给机器可比性用的**：相同切分、相同预算、统一指标口径。

从"磁盘上的产物"到"人脑子里的判断"这一步，前面两个 skill 都不负责。缺了这一步，
Agent 跑得越快，人积累的判断越少，最后的表现是**抗拒继续**——因为每一步都在产生
需要被重新解释的东西，而解释成本没有任何上限。

本 skill 只负责那一步：**把 agent 的工作压缩成人类带宽能吃下的形状，并把"下一步"
变成一个必须由人回答的问题。**

## 核心原则

1. **人的带宽是瓶颈，压缩就是产能。** 一次交互的信息量必须有硬预算。超预算的摘要
   不是"更完整"，是失败——agent 没有提炼出重点。
2. **闸门就是机制。** 过载的根源不是速度快，是缺少"必须经过你"的检查点。
   加总结文档治不好；在流程里加闸门才治得好。
3. **判据先于结果。** 任何实验在跑之前，先写下它检验什么、什么结果算推翻它。
   否则每个结果都是一次新的开放式解释，解释成本无限——这就是过载的数学来源。
4. **结论必须带可推翻条件。** 写不出"什么能推翻它"的，就不是结论，是印象，
   进不了台账。
5. **两个目的分开记，而且必须能往上爬。** 解决实际问题 → 问题台账；
   方法洞见 → 方法台账；**实践需要而方法给不了、且现有框架解释不了的东西 → 理论台账**。
   前两层只回答"发生了什么"，第三层才回答"这个领域缺了什么"。没有第三层，
   做实际问题积累的永远只是经验，长不出可探索的理论问题。
6. **人必须有一张地图。** 摘要卡治"这一次实验说明什么"，
   地图治"**我走过了什么、下一步往哪走**"。缺地图时，人只能被动消费汇报，
   会同时失去判断力与方向感——**而方向只能从走过的地形里推出来**。
   → [experiment-map.md](./references/experiment-map.md)
7. **建模决定必须可追溯，不许临场发挥。** 缺失怎么填、不平衡怎么处理、阈值怎么定、
   切分怎么切——每个会影响结果的选择都必须落到"有文献依据 / 有同构机制可借 / 无来源"三档
   之一。**第三档不许自行决定**：必须把该问题的实测特征讲给人听，并说明需要什么调研，
   然后停下。无来源的决定产生的数据不可用，因为没人知道该拿它跟什么比。
   → [literature-grounding.md](./references/literature-grounding.md)
8. **目的必须落盘，且每轮机械对账。** 人交给 agent 的往往不止一个目的（解决实际问题、
   积累方法洞见、从实践里长出理论课题）。**不落盘 = 没有参照物 ⇒ 偏离必然静默发生。**
   实测教训：一次真实会话里，agent 连续两轮（约 6 次提交探测）完全投入竞赛工程，
   方法学台账零更新，**全程没有任何机制提醒**。文档纪律拦不住这件事——
   只在"有人维护它时才起作用"的规矩，必然在忙的时候失效。
   所以它是脚本：`scripts/goal_guard.py` 每轮结束跑一次，机械报出配比与陈旧度。
   → [goal-persistence.md](./references/goal-persistence.md)
9. **凡是"应当被执行"的规则，都要配齐四件套：字段 + 校验 + fixtures + 变异测试。**
   **只写在文档里的规则不会被执行** —— 本 skill 自己就是这条规律的反复受害者：

   | 规则 | 当时缺的是 | 后果 |
   |---|---|---|
   | 一屏摘要卡的 45 行预算 | **校验** | 每个区块都在截断，预算**永远触发不了**，等于没有预算 |
   | 理论梯子的"其余降级" | **字段** | 降级没有可判定条件 ⇒ **降级从不发生**，条目白占位置两轮 |
   | 证伪条件被触发后要处置 | **校验** | 条目被自己的证据否掉而**没动**，靠人碰巧回头看才发现 |
   | 第 3 档决定"可扫/不可扫" | **字段 + 校验** | 写进参考文档后**无人遵守**，4 个协议块都缺这一节 |
   | 该分流检查自身 | **fixtures + 变异测试** | 会被静默改坏而无从发现 |

   **判据（写完任何规则后问一句）**：**"这条规则现在靠什么被强制执行？"**
   答不出"字段在哪 / 哪个校验会报错 / 哪套 fixtures 覆盖它 / 哪个变异能证明 fixtures 有效"
   —— 那它现在只是一句话，迟早失效。

   **四件的具体形态**（缺一不可）：
   - **字段**：模板里有一个位置承载它（如 `PROTOCOL.template.md` 的"第 3 档决定的分流"表）；
   - **校验**：`check_collab_artifacts.py` 里有一段会报错的检查；
   - **fixtures**：**每条失败路径一个场景**（不是"合法/非法"两场景对——那只能证明检查会响，
     不能定位哪条路径失效），外加一个"不应误报"的对照；
   - **变异测试**：`test_fixtures_mutation.py` 里**每条失败路径一个变异**，证明 fixtures 拦得住。

   → [goal-persistence.md](./references/goal-persistence.md) §"fixtures 自检与变异测试"

## 探究地图（治"不知道走过了什么"）

这是本 skill 里最容易被忽略、但对"人能不能继续做下去"影响最大的一层。
症状很具体：说不出已经试过哪些路线、对数据没有感觉、完全依赖 agent 的汇报、
不知道下一步该往哪走。

**机制：把已有产出汇总成 `QUESTION-MAP.md`，按信息增量分五节，不按时间或文件分。**

| 节 | 使用方式 |
|---|---|
| 一、已确认 | 可直接当已知（须标注来源强度：同源复算 ≠ 独立复核） |
| 二、有冲突 | 使用前必须先看裁定 |
| 三、单来源 | **不得当已知**，引用前先复核 |
| 四、已证伪 | 走过的弯路清单——最容易被重新提出，因此最该显眼 |
| 五、未探究 | **新方向从这一节里选**，而不是让 agent 再给一个建议 |

两条硬要求：

- **不要让 agent 自由发挥写地图**——那会产出又一份汇报。用脚本跨产出目录扫描、
  聚合同一问题上的答案变体，再逐条裁定（见 `references/experiment-map.md` §2）。
- **"已确认"必须标来源强度。** 同一份数据的第二次计算**不是**独立复核；
  同源模型的错误是相关的，会犯同一类错（虚假共识）。

## 多 agent 汇总（fan-out 只在有汇总层时才有价值）

多方向试错是有效的——同一份数据、同一个问题，不同 agent 会给出**6–9 种不同答案**，
包含互相矛盾的机制解释。但**价值只在汇总层存在时出现**；否则 N 份产出就是 N 份噪音。

五条硬纪律（详见 [experiment-map.md](./references/experiment-map.md) §4）：

1. **方向按假设分叉**（数据问题 / 方法问题 / 评测问题），不按参数网格分叉
2. **先独立后汇总**——任何方向在给出结论前不得看到其它方向的结论
3. **每个方向必须声明自己的答案会被什么推翻**
4. **汇总者不得代写"综合结论"**，只能逐方向列答案 + 裁定哪个对
5. **记录"谁没找到什么"**——"没发现问题"与"问题不存在"是两回事

**工具选择**：先不要为 fan-out 造专门系统。用 DSH 现成的
`subagent`（少量方向）/ `workflow`（脚本化 fan-out）/ `.agent-teams`（长期团队）。
本次实测的瓶颈**不在协调，在验证**：并发上限（3 个会话含调度者）卡住吞吐，
而真正的成本在汇总。**在汇总层不存在时扩大 fan-out 只会加速信息过载。**

## 三级台账：经验 → 洞见 → 理论

这是本 skill 里最容易做塌的一环，所以单独说清楚。

| 层 | 回答 | 条目 | 允许的"无答案" |
|---|---|---|---|
| **问题台账** `Q-*` | 这个实际问题长什么样 | 数据怪癖、泄漏陷阱、评测噪声下界、域知识疑问 | 否 |
| **方法台账** `M-*` | 这个方法在此条件下怎么回事 | 可证伪的主张 + 适用边界 + 推翻条件 | 否（必须可证伪） |
| **理论台账** `T-*` | 实践需要什么、方法给不了什么，而现有框架解释不了为什么 | 现象 → 张力 → 理论问题 → 两条方向 | **是**：理论问题本就没有现成答案 |

第三层存在的理由：做实际问题时真正会冒出来的是**"这个方法缺了一块，而缺的那块在
文献里也没有"**。这话在前两层都没有位置——它既不是可证伪的主张（没答案），
也不是一个决策（不改变下一步动作）。没有专门去处，它只会在协议块结束时被写成
一行"开放问题"，然后随协议块一起死掉。

**生成方法是有硬步骤的，不是"多想理论"**：`references/theory-ladder.md` 给出一条
七级梯子（症状 → 机械排除 → 去领域化命题 → 全称化 → 带数字的张力 → 理论问题 →
两条方向 + 区分实验），每级有通过/失败判据，不许跳级。梯子还写明三个会系统性
压制理论生成的压力（局部性陷阱、行动项引力、过早收束）和对应的药。

判定"是否是理论问题"有两条机械规则，校验器会执行：
- `理论问题` 里出现 **"怎么/如何让"** → 工程问题伪装，第 6 级未完成；
- `张力` 里**没有数字** → 只是印象，退回"初步观察"。

## 三层回路

| 层 | 谁跑 | 节奏 | 产出 | 成功标准 |
|---|---|---|---|---|
| **L1 单次运行** | agent 全自动 | 无闸门 | `experiment-standards` 的记录包 | 可复现、可重算 |
| **L2 协议块** | agent 起草、**人批准** | 每块前对齐一次 | `protocols/PROTOCOL-<id>.md` | 跑之前就知道结果怎么读 |
| **L3 决策回路** | 人决策、agent 执行 | 每块后一次 | 摘要卡 + 决策日志 + 三级台账 | 人能 5 分钟接手并下指令 |

**L2 是治过载的真正机制。** L1 保持不变（记录包照旧，那是可复现性的地基），
L3 是输出侧的压缩，L2 是输入侧的预注册。三者缺一不可：
没有 L2，L3 的摘要只能事后圆场；没有 L3，L2 写完就没人读。

## 工作流

按顺序执行。标 ⛔ 的步骤**必须停下来等人**。

### 0. 开题：写 `CHARTER.md`（一个课题一次）

在写任何代码之前。内容：要解决的实际问题一句话、成功判据（可观测）、
当前已知（带着证据等级）、当前未知、以及**评测噪声下界**。

**同时必须写 `<goals>` 块** —— 这是整套流程里唯一能防止"跑着跑着就偏了"的东西：

```markdown
<goals>
- `basis`: 解决实际问题 —— <一句话，可观测的成功判据>
- `method`: 积累方法洞见 —— <要摸清什么边界/陷阱>
- `bridge`: 从实践里长出理论课题 —— <要沉淀成什么样的可研究方向>
</goals>
```

> ⚠️ **为什么必须显式声明多个目的**：只写 `basis`，agent 会一路做工程（**已实际发生**：
> 一次会话里连续两轮纯竞赛工程，方法学台账零更新，且偏离完全静默）；
> 只写 `method`，会脱离真实约束变成空想。
> `bridge` 是"做实际问题能积累出理论洞见"这句话的可执行形态。
> → [goal-persistence.md](./references/goal-persistence.md)

```bash
python scripts/score_noise_floor.py --n-test <N> --formula <公式> --tau <τ> --k <k>
```

> ✅ **完成标志**: `CHARTER.md` 存在；`<goals>` 块里 ≥2 个目的（建议 3 个）；
> "评测噪声下界"一节填的是数字不是形容词。

### 1. 勘察数据现实，建问题台账

在建模之前，先回答"这份数据有什么和简介不一样的地方"。每条进
`ledgers/problem-<topic>.md`，格式见 [ledgers.md](./references/ledgers.md)。

先勘察后建模，是因为**这类事实最便宜也最值钱**：它们会直接改掉后面的所有实验设计，
而且一旦模型跑起来就没人再有动力回头看数据了。

> ✅ **完成标志**: 问题台账 ≥3 条，每条带证据（命令/行数/文件）和证据等级。

### 2. 查依据：每个建模决定先定档 ⛔

在起草协议块**之前**做，因为这一步可能直接产生一个要人回答的问题、从而改掉整块的设计。

对块内**每一个会影响结果的选择**（缺失填充、样本权重、重采样比例、窗口/视野长度、
标注容差、负样本排除带、切分方式、阈值选择法、模型数与早停……）问一句
**"换一个值结果会变吗？"** 会变 → 它是建模决定 → 按三档定档：

| 档 | 条件 | 动作 |
|---|---|---|
| **1 有文献依据** | 能引到具体节号/表号，且文献实测范围覆盖本问题关键特征 | 直接引用，写数字与出处 |
| **2 有同构机制可借** | 指名机制 + 本问题确实存在该机制 | **必须**同时写明外推边界，并把它变成协议块里一条可被证伪的预测 |
| **3 无来源** | 查不到，或文献范围不覆盖 | ⛔ **不许自行决定**，按下面五栏向人汇报后停下 |

第 3 档的汇报五栏（平实的话，不许造词）：**这是什么选择 / 为什么必须选 / 这个问题的特征
（必须是实测数字） / 现有文献覆盖到哪 / 需要什么调研**。判据：人听完能自己判断这个问题
是难是易、值不值得投入。

每条依据都要附**范围戳**：`论文声明的适用范围 | 它实际测了什么 | 因此不能用来支持什么`。
两者不一致处正是误用高发区。

> ⛔ **停**：第 3 档未获人回答之前，不许起草协议块、不许"先用一个合理默认值跑一版看看"。
> 详见 [literature-grounding.md](./references/literature-grounding.md)。

### 3. 起草协议块 ⛔

每轮只起草**一个**块，用 [protocol-block.md](./references/protocol-block.md) 的模板。
核心是预注册：主指标、最小可检测效应、对照、成功/失败判据、**以及这个结果绝不能
被用来声称什么**。每个建模决定要带**档位 + 依据**字段（第 2 步的产物）。

**判据是"多档"时必须写 `判据优先级:` 一行**（谁优先、各档条件是否互斥且穷尽，
以及档里用到的**区间**怎么算）。少了它，实测一旦落在两档之间的缝里，
"哪一档成立"就由解释者决定 —— `P-BOILER-012` 实测过这个形态，
校验器现在会对"≥2 档但没有优先级"直接 FAIL。

> ⛔ **停**：把协议块给用户看，等批准。批准前不写任何会消耗算力的代码。

### 4. 执行 L1

按 `experiment-standards` 全套规范跑（记录包、预测分布落盘、逐 epoch 指标）。
本 skill 不改变 L1 的任何要求。跑完立刻 `update_results_json`。

**一个闸门 = 一个协议块。** 不许在同一轮里接着跑第二个块。

### 5. 生成摘要卡 `DIGEST-<block-id>.md`

用 [digest-card.md](./references/digest-card.md) 的模板。字段和字符预算是硬的。
自检：

```bash
python scripts/check_collab_artifacts.py --digest runs/<...>/DIGEST-<id>.md
```

> ✅ **完成标志**: 校验脚本通过（标题齐全、预算未超、结尾恰好一个问题）。

### 6. 更新台账（三级，逐级判断）

把本块产生的**可推翻结论**写进方法台账。机制字段认定是"方法本身的性质"的，才进方法台账；
"实现问题/调参问题"进决策日志就够，不进台账（除非复现三次以上）。

然后按 [theory-ladder.md](./references/theory-ladder.md) 判断本块是否产生了
**"实践需要而方法给不了、且现有框架解释不了"**的东西。触发条件（任一满足）：

- 某条方法台账条目已到 `稳定`，且 `被用于` 指向 ≥2 个协议块；
- 同一落差在**两个不同课题**上出现（此时它大概率已经是理论问题）；
- 你提出了一个现有框架**按定义就覆盖不到**的问题。

不触发的情况同样要判断：落差小于评测噪声下界（那是噪声）；落差能被调参消除
（那是方法台账的事）；只有一个课题上出现且证据是 `薄`（还太早）。

> ✅ **完成标志**: 三级台账都已判断过。理论台账可以为空，但"判断过"必须留下痕迹
> （例如在决策日志里写一行"本块无理论入账，原因：…"）。

### 7. ⛔ 停：交决策卡

摘要卡结尾的"待你回答"必须是**恰好一个问题**。agent 给出自荐（GO / NO-GO / 换方向）
和理由，但**不替你决定**。你回答后，记录进 `DECISIONS.md`，然后回到步骤 3。

**写进 `DECISIONS.md` 的"等你"行必须写全三件套**（缺一件 ⇒ 校验器 FAIL）：

| 列 | 写什么 | 硬要求 |
|---|---|---|
| `你会拿到什么` | 你做完这个决定**会读到一个什么数** | 必须含**数字**，或明确的`打平`/`无信息` |
| `你要花什么` | 稀缺资源与数量（额度 / 时间 / 钱） | 必须含数量 |
| `前置条件` | 什么必须先成立（例如"你还剩 ≥1 次额度"） | 没有就写`无` |

**立这条的实测原因**：`DECISIONS.md` 里那条唯一的待决定原先只有「决定 + 理由 + 状态」，
理由栏写的是"**信息量大**" —— 那是 agent 的判断，不是给你算账的信息。
你真正需要知道的三件事**一件都没写**。这正是本 skill 立文时的那句话：
"看不懂 agent 要求我抉择的选项"。
⇒ 只对**状态含 `等你`** 的行强制（agent 自己的待办用 `待回改` 等标记，不受此约束，
也不会被一屏列进"该你决定"——把 agent 的活推给人，比不写更坏）。

```bash
python scripts/check_collab_artifacts.py --decisions DECISIONS.md
```

> ⛔ **停**：在用户回答之前，不开始下一个协议块，也不"顺手"跑点别的。

### 8. 维护探究地图（每 2–3 个块，或每次 fan-out 之后）

把新增的确认/冲突/证伪/未探究更新进 `QUESTION-MAP.md`。这一步**不能省**：
省掉它，人会在几个块之后失去地形，然后开始抗拒——而那时问题已经不在流程上了。

```bash
# 跨产出目录扫描同一问题上的答案变体，作为地图原料
python scripts/conflict_scan.py --runs runs/ --out CONTRADICTIONS.md
```

```bash
# 重生成产物索引：把"活产物 → 谁引用它"列成表，并检查引用完整性
# skill 目录**自动**算外部根（工作区按设计就要引用 skill 的判据文件，不该由人记得传）；
# 竞赛数据 / 参考文献目录要自己用 --root 传，否则它们会被报成"未解析引用"。
python scripts/artifact_index.py --workspace <工作区> \
  --root <竞赛数据目录> --root <参考文献目录> --out <工作区>/INDEX.md
```

**地图与索引是两份东西，不能互相替代**：`MAP.md` 是**叙事**（我走过了什么、下一步去哪），
`INDEX.md` 是**机械清单**（这个数字背后的文件在哪、谁在引用它）。
索引由脚本生成、**不要手改**；它同时报出"活文档点名了但哪里都找不到的文件"——
第 21 轮第一次跑就报出 5 处，其中 3 处是**命名漂移**（文档写 `LEDGER-theory-x.md`，
活台账叫 `theory-x.md`）⇒ **人按文档去找那个文件是找不到的，而没人会为此报错**。

⚠️ 报出"未解析"时**先分辨它是不是误报**（第 28 轮：16 条报告里 12 条是误报）：
工作区文档引用 skill 自己的 `references/*.md`、`scripts/*.py` 是**必然发生**的，
所以 skill 目录被自动登记为外部根；剩下的通常是**数据目录没传 `--root`**。
⇒ 修的顺序是 ①改名字漂移 ②补 `--root` ③才写进 EXTERNAL 豁免表。
**误报最坏的后果不是浪费一次运行，是训练人忽略整份报告。**

> ✅ **完成标志**: `artifact_index.py` 退出 `0`（未解析引用 0 个）。

> ✅ **完成标志**: `QUESTION-MAP.md` 的五节都已更新；每个"已确认"都标了来源强度；
> 新方向是从"未探究"一节里选的，而不是 agent 临时提议的。

### 9. 跑目标守卫（**每轮结束，不设间隔**）⛔

```bash
python scripts/goal_guard.py \
  --charter CHARTER.md --ledgers ledgers/ \
  --protocols protocols/ runs/ --decisions DECISIONS.md \
  --theory-ledger ledgers/theory-<topic>.md
```

**这是治"跑着跑着就偏了"的唯一运行时机制，不能按"每 2–3 块"的节奏省。**
它机械报出八类事实：**配比** / **方法学滞后** / **理论闭环（双向链接）** /
**证伪条件待核对** / **挂起到期与降级去向** / **悬空理论引用（含「事后归因」标记）** /
**未打 `[goal]` 标记的条目** / **人面 headine 是否"新"且"短"**。
每一条判据都有"立此的实测原因"，**不要只记结论、不问它为什么在那儿**。

→ 判据 1–8 的逐条说明（含每条的真实代价）：[guard-criteria.md](./references/guard-criteria.md)

代价是每轮一条命令；收益是偏离**会被看见**，而不是等人中途打断。
→ [goal-persistence.md](./references/goal-persistence.md)（守卫）·
[theory-to-experiment.md](./references/theory-to-experiment.md)（理论闭环）

> ⛔ **完成标志**: 退出码 `0`。若为 `2`（偏离已确认），**先回到 `CHARTER.md` 第 0 节
> 说明下一步推进哪个目的，再开新块**；不许"先把这个块跑完再说"。

**为什么这一条必须独立于验收标准**：验收标准里的"理论入账测试"是**事后**的
（每 5 块才查一次），而偏离的窗口恰恰是那 2–5 块。
两者互补，不能互相替代。→ [goal-persistence.md](./references/goal-persistence.md)

### 10. 交一屏状态（**每轮结束，与守卫同时**）

```bash
python scripts/status.py --charter CHARTER.md --ledgers ledgers/ \
  --protocols protocols/ runs/ --decisions DECISIONS.md \
  --theory-ledger ledgers/theory-<topic>.md
```

**守卫是机器脸（退出码），这一步是人脸（一屏）。** 两者读同一批文件，缺一不可：
只有守卫，人看不到配比；只有这一屏，就没东西能拦住偏离。

它按**目的与块**组织（不是按时间、也不是按文件），回答四件事：
**这几轮在干嘛（工程/方法学各占多少）· 目的健康度 · 理论闭环 · 该你决定什么**。
硬预算 **≤45 行**；超预算不是"稍长一点"，是没提炼出重点。

> ✅ **完成标志**: 输出 ≤45 行，且"状态"一行来自 `CHARTER.md` 的 `<headline>` 块
> （不是 agent 现编的）。→ [human-facing-output.md](./references/human-facing-output.md) §3.6

## 验收标准（这套流程自身的对错判据）

流程的好坏不靠感觉，靠八条测试。**前四条检验课题，后四条检验流程本身** ——
后者是唯一"不看你做了什么、只看这套流程还转不转"的判据。
**任一条不过，就地修，不要继续往下堆。**

| # | 测试 | 一句话判据 | 机械形式 |
|---|---|---|---|
| 1 | 五分钟测试 | 只读摘要卡头两行+最后两行，能说出"发生了什么、下一步选什么" | `--package` / `--workspace-entry` |
| 2 | 台账"被用"测试 | 方法台账每 3 条至少 1 条 `被用于` 指向具体块 | `--ledger` |
| 3 | 噪声免疫测试 | 小于 MDE 的改进被如实记成 `薄` | `--digest` |
| 4 | 理论入账测试 | 每 5 块至少 1 条 `成熟度 ≥ 可研究的问题`，或写明为什么没有 | `--ledger` |
| 5 | 目的持久性测试 | 每轮 `goal_guard.py` 退出 `0` | `goal_guard.py` |
| 6 | 规则可执行性测试 | 新规则配齐**四件套**（字段+校验+fixtures+变异） | `--mutation-test` |
| 7 | 报告可达性测试 | 校验脚本的 FAIL 在裸控制台上**读得到、不崩** | `check_console_safe.py` |
| 8 | 测量可信性测试 | 打分**之前**确认产出还在；空产出记 `INVALID` 不记 0 分 | `check_run_integrity.py` |
| 9 | 提交可复现测试 | 交出去的代码按它自己 README 那条命令跑，**逐行**得到提交的那份结果 | `check_package_repro.py` + `check_submission.py --code-zip` |

> **为什么要下沉**：本文件是每次触发都进上下文的那一层，它自己有预算。
> 而本 skill 立文治的正是"信息量超过人的带宽"——**skill 自己不该成为那个过载源**。
> 九条测试的**逐条说明、每条的真实代价、以及为什么它必须独立成一条**：
> → **[acceptance-tests.md](./references/acceptance-tests.md)**

## 洞见标准（什么叫"积累了方法洞见"）

方法台账与理论台账的门槛不同，不要混用：

**进方法台账**（回答"这个方法怎么回事"，必须可证伪）——四条全满足：

1. **是一个主张**，不是一次观察（"SWAG 在 N<500 时方差被低估" 而非 "SWAG 效果不好"）；
2. **带适用边界**（在什么条件下成立，在什么条件下不成立）；
3. **有 ≥2 次独立复现**（不同数据切分或不同任务；单次一律记 `薄`）；
4. **写得出推翻条件**（什么实验会证伪它）。

**进理论台账**（回答"这个领域缺什么"，允许暂无答案）——四条全满足：

1. **有实测的缺口**：张力里有数字，且落差大于评测噪声下界；
2. **完成机械排除**：换过实现、超参/预算、种子、切分，落差仍在；
3. **完成全称化**：能用方法学语言陈述，且能指出至少一处不相关任务上的同构现象；
4. **`理论问题` 里没有"怎么/如何让"**，且写得出"什么能证伪这条理论问题"
   （即它其实是个工程问题）。

写不满的一律先留在摘要卡的"机制"字段里当候选，别急着升格。
**升格门槛放宽的那一刻，台账就从判断记录退化成措辞收藏。**

## 普适性：什么必须是通用的，什么允许来自具体课题

本 skill 的第一个实例是一个具体竞赛。**"有实例"与"被实例绑死"是两件事**，界线只有一条：

| 层 | 例子 | 允许依赖具体课题吗 |
|---|---|---|
| **判据层**：`scripts/*.py` 的**代码**（字符串常量、默认值）、`assets/templates/*.md` 正文 | 列名、数据根、公式名、阈值 | **不许**：做成参数 / 注册表条目 / 按内容自动识别；必要的例外写 `# genericity-ok: <理由>` |
| **证据层**：`#` 注释、docstring、`references/`、`assets/samples/` | "某课题三份提交的 README 命令是从别处复制的，交 11 行复现成 34 行" | **允许，而且应当保留** |

证据层不清洗的理由与 `B8`/`B24` 同源：**没有代价的规则会退化成口号**。所以样张名中性
（`CHARTER-sample.md`）、出处写在样张内部；注释保留数字，去掉只有实例才有意义的编号。

这条界线是**检查**不是愿望：`scripts/check_genericity.py`（0 才算干净，只扫判据层；
实测全 skill 49/60 个文件命中实例词 ⇒ 整改后判据层为 0）。判据与豁免规则见该脚本 docstring。
