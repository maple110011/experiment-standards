# DECISIONS — <课题名>

> 每次回答摘要卡的"待你回答"后追加一行。这是**人的判断记录**，不是 agent 的日志。
> 用途：三个月后回看"当时为什么选这条路"，以及识别"同一个选择被反复做"。

## 格式

| 日期 | 块号 | 决定 | 谁定的 | 理由 | 你会拿到什么 | 你要花什么 | 前置条件 | 状态 |
|---|---|---|---|---|---|---|---|---|
| <YYYY-MM-DD> | <P-XXX-001> | <做了什么决定> | <用户 / agent（依据…）> | <为什么> | — | — | — | 生效 |

**`状态` 只有这几种，且它们的区别是有后果的**：

| 取值 | 含义 | 后果 |
|---|---|---|
| `生效` / `已封存` / `已撤销` | 已经定了 | 不需要"决策三件套" |
| `**待执行（等你）**` | **等人决定** | **必须写全三件套**，且会被一屏列进"该你决定" |
| `待回改` / `待补` / `待定` | **agent 自己的待办** | 不需要三件套；一屏会把它列在"agent 自己的未完成项"下，**不会说成"该你决定"** |

## 决策三件套（"等你"的行必填）

| 列 | 写什么 | 硬要求 |
|---|---|---|
| `你会拿到什么` | 做完这个决定**会读到一个什么数** | 必须含**数字**，或明确的`打平`/`无信息` |
| `你要花什么` | 稀缺资源与数量（额度 / 时间 / 钱） | 必须含数量 |
| `前置条件` | 什么必须先成立（如"你还剩 ≥1 次提交额度"） | 没有就写`无` |

> **为什么强制**：实测中那条唯一的待决定原先只写"信息量大"——
> 那是 agent 的判断，不是给人算账的信息；人无法据此决定值不值得花。
> 三件套缺任何一件，`check_collab_artifacts.py --decisions` 会 FAIL。

```bash
python scripts/check_collab_artifacts.py --decisions DECISIONS.md
```

`破例`（块内跑变体 / 连跑两块 / 不出摘要卡）只能填 `references/cadence.md` §3 里的四种之一，
写进 `理由` 列即可。**破例只能由人发起**；agent 自行放宽属于流程违规，
应在下一次摘要卡的"意外"栏里报告。
