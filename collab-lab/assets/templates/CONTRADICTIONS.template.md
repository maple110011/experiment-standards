# CONTRADICTIONS — <课题名>

> **用途**：多方向 fan-out 只有在汇总层存在时才产生价值。
> N 个方向给出 N 份产出而不做比对，等于把 N 份噪音堆给人。
>
> 原料：`python scripts/conflict_scan.py --runs runs/ --questions questions.json --out scan.txt`
> 裁定：由人/agent 完成，**脚本不能裁定**。
> 规则见 `references/experiment-map.md` §3–§4。

## 格式

```
### X-<序号> <一句话问题>
各方向答:  <方向 A: 答案 + 出处> / <方向 B: 答案 + 出处> / …
分歧类型:  真矛盾 | 同一个词指不同的量 | 口径不同 | 一方算错
裁定:      <结论 + 依据（哪个可复算）>
裁定依据:  <文件 / 命令>
该冲突暴露了什么: <流程缺陷，而不是"谁不认真">
```

**最后那一栏是台账的价值所在。** 单条冲突只是麻烦；十条冲突指向同一个流程缺陷时，
那就是流程改进的入口，而不是十次"运气不好"。

## 例（来自一次真实评估）

```
### X-1 噪声下界该报多少
各方向答:  A: 9 分（脚本默认 τ=0.05） / B: 7.75 分（τ=0.05 全枚举） /
           C: 14–20 分（两次独立评测分数差的 MDE80） /
           D: 17 分（975 格点 95% 噪声带下界） / E: 区间 [0.017, 10.05]
分歧类型:  同一个词指不同的量
裁定:      五者不是互相矛盾，而是四种不同的量。正确做法是报「量的名称 + 口径 +
           对未知参数（τ）的依赖」，禁止给单一数字门槛。
裁定依据:  score_noise_floor 全枚举输出 + 各方自带的扫描日志
该冲突暴露了什么: 「数值必须带定义（量名 / 口径 / 步长）」没有被强制执行。
           同一份数据上 5 个方向各自给出了一个数字，没有人被要求说明它是什么量。
```
