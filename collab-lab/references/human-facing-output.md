# 给人看的交付物：别把记录体系当成人机界面

> 这一节治的是一个具体的失败：**所有工件都合格，人却无法据此决策。**
>
> 实测场景：协议块通过了校验器、摘要卡字段齐全、地图五节齐备，
> 而人的反馈是——"**我完全不知道我在决策什么，不知道它们会有什么影响。**"

## 1. 失败长什么样（三条具体错因）

| 错因 | 表现 | 例子（真实发生过） |
|---|---|---|
| **把代理量当成了选项** | 选项写的是"K 能否推得更远"，而人想知道的是"这课题还能不能往下走" | 人问"要不要跑 A"，卡片答"G 实测值是多少" |
| **用术语的正确性描述结果** | "框架可以推得更远"是关于**汇报者自己**的话，不是关于**实验**的话 | 人读完不知道采纳后会发生什么变化 |
| **没说在拿什么做比较** | "0.66 对比 1.0"里的 1.0 从哪来？不说清，这个比较就没有意义 | 判据 0.79 来自合成场景，而汇报里没标 |

## 2. 根因：记录体系的组织方式被直接当成了界面

本 skill 建了九个字段的摘要卡、三级台账、七级梯子、五节地图。
**这些全是 agent 用的记录卫生器材。** 给人看的只有开头一句话和结尾一个问题——
中间那段"**你实际在按什么权衡**"从来没有被写出来过。

具体地说，记录体系按**证据状态**组织（已确认 / 有冲突 / 单来源 / 已证伪），
而人按**问题**组织：

| 记录体系的组织 | 人的组织 |
|---|---|
| 这条证据是稳定还是薄？ | **数据到底能给我什么？** |
| 这里有几条独立来源？ | **这个测量能不能支撑判断？** |
| 这条被证伪了吗？ | **哪条路被排除过，别再让我走？** |
| 还有什么未探究？ | **我现在有哪些选项，代价分别是什么？** |

**同一批事实，两种顺序。** 用前者组织，人读得懂每个句子却拼不出决策。

## 3. 处方

### 3.1 地图按人提问的顺序组织，五节固定

1. **数据到底能给你什么**（含"实际可用"与"名义上"的差）
2. **判分方式有什么坑**（会静默毁掉努力的那些）
3. **你现在最需要知道的两三件事**（每件都要有"这对你意味着什么"）
4. **已排除的路**（含"还会听到的建议"一栏——这条直接防止重复劳动）
5. **方向选项**（每项写"你会拿到什么 / 你要花什么 / 前置条件"）

### 3.2 每个发现必须带"这对你意味着什么"

只有数字 + 口径是不够的。缺这一句，人读完不知道它影响哪个动作。

反例（合格但不给人用）：
> `AUC_LOEO = 0.77，判据 0.79，事件级分辨率 1/11 ≈ 0.09`

正例：
> **用 9–11 次故障测出来的精度是 0.1，而信号离及格线只差 0.02 ——
> 比精度还小 5 倍。所以本地没法定你的改进有没有效，不是"还差一点"，是量具不够精。**

### 3.3 "已排除的路"要写清"你还会听到什么建议"

人重复走死路的主要来源不是遗忘，是**别的 agent 会重新提出同一个建议**。
把"常见建议"和"为什么没用"并排列出，比只写"已排除"有效得多。

### 3.4 选项写"得到什么 / 花掉什么"，不写"是否满足某性质"

人在取舍，不在核对。所以每个选项给出：

```
- 你会拿到什么：<一句可验证的收益>
- 你要花什么：<时间/额度/机会成本>
- 前置条件：<没有它这个选项做不了>
```

### 3.6 三种"给人看"的交付物，各治一件事（**不能互相替代**）

| 交付物 | 治什么 | 读者愿意花的时间 | 组织方式 |
|---|---|---|---|
| `DIGEST-<块>.md` | **这一次实验说明什么** | 5 分钟 | 固定字段 + 硬字符预算 |
| `MAP.md` | **我走过了什么、下一步往哪走** | 想深看时 | 按人提问的顺序，长文 |
| **`scripts/status.py` 的输出** | **此刻我在哪、配比如何、该我决定什么** | **30 秒** | 按**目的与块**，一屏 ≤45 行 |

前两者都假设人愿意读几百到几万字节。**第三种假设人只有 30 秒** ——
而"不知道 agent 在干嘛"这个症状恰恰发生在人**没时间读长文**的时候。

**这一屏的四条硬要求**（都是实测踩出来的）：

1. **先姿态后内容**：第一行必须是"我们在哪、守不守得住"，
   且**来自 `CHARTER.md` 的 `<headline>` 块**，不是 agent 现编的。
2. **不并排显示两列中文**：宽列中文在等宽终端上会被读成一团。
   （本脚本开发时我本人就把两列看混过 —— 那不是排版小瑕疵，是**读错**。）
   宁可分组换行，也不要"对齐好看"。
3. **配比必须报**："最近 N 块里纯工程 X 块、含方法学 Y 块"。
   这是"agent 在干嘛"最直接的答案，也是偏离最早的可见信号。
4. **超预算就重写**，不要"稍微超一点"（同 §1 的摘要卡原则）。

### 3.7 一个自检器只会说 OK，等于没有自检器（**写这一节的直接原因**）

做 `status.py` 的 45 行预算时，我按惯例写了个"预算测试"：正常输入应退出 0、膨胀输入应退出 1。
**测试通过了** —— 但通过的方式是**两条都返回 0**，而我把"正常=0"当成了成功的一半，
差点收工。真实情况是：**预算永远触发不了**，因为我在每个区块都写了截断
（`gaps[:4]`、`pend[:4]`…），行数根本长不到 45。

**一个无法触发的约束，和没有这个约束完全一样**，而且更坏 ——
因为它会让人**以为**有约束。

**修法与判据**：
1. **删掉所有硬截断**，只保留一个截断机制（预算本身）；
2. 自检必须**断言两个方向**：正常输入 → 0 **且** 膨胀输入 → 1；
   只报"正常输入通过"不算通过；
3. 把这类反向自检**并入 `check_collab_artifacts.py --self-test`**，
   否则它是一次性验证，下次改代码时不会被重跑。

**一般化**：任何"限制类"机制（字符预算、行数预算、并发上限、额度）
都必须配一个**反向用例**证明它真的会拦人。
**只会说 OK 的校验器，比没有校验器更危险。**

### 3.5 硬自检：术语剥离测试

**把全部自造术语删掉后，人还能说出"这个决定会影响什么"吗？** 不能 → 卡片不合格，重写。

自造术语包括所有本 skill 定义的量名（`AUC_LOEO`、`MDE`、`G`、`F`、`Δ`、`ICC`、
"设计效应"、"分辨率"），以及所有本 skill 定义的工件名（协议块、台账、梯子、地图）。
**它们在 agent 之间可以随便用**（那是效率），但**出现在给人做决定的段落里就是失败**。

一个正例（重写后）：

> **"故障算 9 次还是 10 次"不影响任何结论** —— 实测已证明。
> 所以这件事可以关掉，不要再花时间。真正卡住你的是：**这套数据测不出改进。**

## 3.8 结果先落盘，报告只是渲染（**写这一节的直接原因：真丢了一整轮计算**）

一个跑了 **327 秒**的合成扫描（6480 组合 × 5 种子），在最后"打印自检"那一行抛
`UnicodeEncodeError` —— 提示里有个 `⓪`（U+24EA），而 cp936 里没有这个字符。
**结果写在报告之后 ⇒ 整轮计算全丢，只能重跑。**

⇒ 两条纪律，**顺序那一条与编码无关，任何异常都适用**：

1. **机器可读的结果先写文件，再打印任何报告。**
   报告只是这份文件的**渲染**。这样报告崩了，代价是"这次没看到报告"，
   而不是"这次的计算白跑了"。
   —— 更一般地说：**别把"人看的那一份"当成结果本身。**
2. **输出要兜底**：`sys.stdout/stderr` 的 `errors` 设成 `replace`，
   不可编码的字符降级成 `?` 而不是抛异常。skill 自己的脚本用
   `scripts/subproc.py`（import 即生效）；工作区里的一次性脚本抄这三行：

   ```python
   for _s in (sys.stdout, sys.stderr):
       try: _s.reconfigure(errors="replace")
       except Exception: pass
   ```

   改完用 `python scripts/check_console_safe.py <你的脚本.py>` 核一遍。

> ⚠️ **"不崩"与"好看"是两件事。** 兜底会把 `⇒`、`⓪`、emoji 印成 `?`，
> 而**人脸那一屏上出现一个孤零零的 `?` 也是噪声**。
> 所以：**打印给人看的字符串，优先挑目标编码能印出来的字符**
> （本仓库实测：`⇒`→`=>`、`⓪`→`[0]`、`⏳`→`[挂起]`）。
> 兜底是安全网，不是排版方案。

## 3.9 地图 ≠ 索引：一个是叙事，一个是机械清单

「我无法利用 agent 产出的结果和数据」有两个成因：**文件没留下**（已由"先落盘"治），
以及**留下了但我不知道它在哪**。后者不是叙事能解决的 —— 再好的地图也不会列出
两百多个产物文件谁引用谁。

所以两份东西各管一半，**不能互相替代**：

| | `MAP.md` | `INDEX.md`（`scripts/artifact_index.py` 生成） |
|---|---|---|
| 体裁 | 散文，按**人提问的顺序**组织 | 表格，按**引用关系**组织 |
| 回答 | "我走过了什么、下一步往哪走" | "**这个数字背后的文件在哪、谁在引用它**" |
| 维护 | 人写、人改 | 脚本生成，**不要手改** |
| 失败形态 | 太长、没人读完 | 太吵（把草稿目录也列进来） |

**排序按"被谁引用"，不按"被引用多少次"**：第一版按总数排序，前 17 行全是
5 个提交包**互相引用**的 `README.md`（一个 6 元团），真正要找的
`T1_block_grid.py`（被 5 份核心文档引用）被挤到第 18 行。
⇒ **"被引用次数多"不等于"重要"，要问的是"被谁引用"。**

**它顺带机械地治住一种静默漂移**：文档用散文点名文件，而"提到"与"存在"之间
本来没有任何关系。第一次跑就报出 5 处（3 处是命名漂移）——
**人按文档去找那个文件是找不到的，而没人会为此报错**。

## 4. 与其它文档的关系

- `map` 模板（`assets/templates/MAP.template.md`）是这一节的可填写版本；
- 摘要卡（`references/digest-card.md`）管"这一次实验说明了什么"，
  **不承担**"整体地形与方向"的职责——两者不能互相替代；
- 决策卡那三行（自荐 / 理由 / 风险）**必须用得到什么、花掉什么来写**，
  而不是"某性质是否满足"。

## 5. 失败模式

| 症状 | 诊断 | 修法 |
|---|---|---|
| 人读完了却问"所以呢" | 缺"这对你意味着什么" | 每个发现补一句影响 |
| 人不知道选项之间差在哪 | 选项按性质描述而非代价 | 改成"得到什么 / 花掉什么" |
| 人开始问"这个量是什么" | 术语泄漏进决策段 | 术语剥离测试，重写 |
| 人无法判断某个数字可不可信 | 没写它在拿什么做比较 | 标明比较基准及其来源 |
| 同一建议被反复提出 | "已排除的路"只写结论 | 补"还会听到的建议"一栏 |
| 地图越写越长 | 按证据状态组织 | 改成按人的提问顺序 |
