# 摘要卡：人用界面

> **模板**: `assets/templates/DIGEST.template.md`
> **自检**: `python scripts/check_collab_artifacts.py --digest <path>`

## 设计约束：预算是硬的

摘要卡不是"简短的报告"，是一份**带宽预算固定的接口**。字段固定，字符预算固定，
结尾必须是恰好一个问题。超预算的处理方式不是"稍微超一点"，是**重写**——
超预算说明 agent 自己也没提炼出重点，把负担转嫁给了人。

| 字段 | 预算 | 硬性要求 |
|---|---|---|
| 结论 | ≤40 字 | 一句话；带强度标签 |
| 对比 | ≤4 行表格 | 只写动了的；每行必须有不确定度 |
| 意外 | ≤3 条 | 写"无"必须同时说明覆盖面 |
| 机制 | ≤3 条，每条一行 | **必须标注三分类之一** |
| 堵点 | ≤3 条 | 卡在哪 + 已排除哪些原因 |
| 开放 | ≤3 条 | 每条附"什么能解决它" |
| 决策卡 | 3 行 | agent 自荐 + 理由 + 风险 |
| 待你回答 | **恰好 1 个问题 + 2–4 个互斥选项** | 不多不少 |

## 1. 结论：一句话 + 强度标签

强度标签只有四个，**不许自创**，也不许每次都填同一个：

| 标签 | 含义 | 什么情况下可用 |
|---|---|---|
| `强` | 在多个切分/种子上复现，且通过了对照 | 需要 ≥2 次独立复现 |
| `薄` | 单次运行，或效应小于最小可检测效应 | 默认状态 |
| `不稳` | 复现之间结论矛盾 | 必须写清矛盾在哪 |
| `?` | 推测，来自文献或推理，无本课题证据 | 不得作为下游前提 |

**如果这个 session 每次都在填 `薄`，说明不是结果保守，是没有在复现。** 这是给
agent 的检查信号：连续 3 张卡都是 `薄` 而没有任何复现动作，说明流程在空转。

## 2. 对比：只写动了的

每一行格式固定为：`对象 | 基线 | 本次 | 效应量 | 不确定度`。

三条纪律：

- **基线必须来自同一个记录包**（同切分、同口径），不是记忆中的数字；
- **效应量必须与最小可检测效应并排**。没有这个对照，读者无法判断 0.3 分是信号还是噪声；
- **没动的东西不进表格。** 想记录全部结果，那是 `results_partial.json` 的职责，
  不是摘要卡的。

## 3. 意外：预料之外的事

这一栏的价值高于"结论"，因为结论往往在预期之内，而**意外是唯一能改掉假设的东西**。

覆盖面声明是硬要求。写"无"的时候必须写成"无（覆盖了 X、Y、Z，未检查 W）"。
一个从不上报异常的监控不是干净的监控，是拔掉的监控——这条对 agent 自己同样成立。

## 4. 机制：洞见的唯一入口

每条必须从下面三分类里选一个，**不允许含糊**：

| 分类 | 含义 | 后续动作 |
|---|---|---|
| **实现问题** | 代码/数据管道/环境错误 | 修掉，**不进方法台账** |
| **调参问题** | 超参、预算、调度没调好 | 调完重测，**不进方法台账** |
| **方法本身的性质** | 该方法在此条件下的固有行为 | 写进方法台账，带适用边界 |

这一栏是整套流程里最重要的一格。没有它，所有失败都会被记成"这次没跑好"，
方法层面的积累恒为零；有了它，"这个坑我踩过了"才有可能变成"这个方法的边界在这里"。

**升级规则**：同一个"实现问题"或"调参问题"在三次独立尝试后仍然撞墙，
必须升级标记为**疑似方法性质**并在方法台账里开一条 `?`。三次是经验阈值——
一次是意外，两次是巧合，三次开始像性质。

### 机制栏同时是理论台账的入口

"方法本身的性质"这一格里，有一条特殊的情况值得单独盯：

> 这里**需要**的是 X，方法**给**的是 Y，而现有框架**说不了**为什么两者对不上。

这不是"这个方法不行"，而是一个缺口。只要有这种句子出现，就在摘要卡末尾的
"待你回答"里给它留位置——或按 `references/theory-ladder.md` 的触发条件，
把它送进理论台账。

**判据是机械的**：如果这句话里你写不出一个数字（差多少、在什么条件下、多大分辨率），
那它还只是印象，先留在这一栏当候选；一旦能写出数字，它就有资格往上爬。

## 5. 堵点：卡在哪

每条写三件事：卡在什么上、是数据问题还是方法问题、**已经排除了哪些原因**。

"已排除"比"卡在哪"更值钱：它防止下一轮重复同样的排查，也防止把未排除的原因
当成已排除。给不出已排除列表的堵点，实际上还没排查过，只是遇到了困难。

## 6. 开放：留给后面的问题

每条附"什么能解决它"。写不出解决方式的问题不是开放问题，是抱怨。
开放问题应同步进台账的"开放"区。

## 7. 决策卡：agent 自荐，人决定

```
自荐:   GO / NO-GO / 换方向 / 先补一个更便宜的实验
理由:   一行，引用本卡的具体字段
风险:   一行，这个自荐最可能错在哪里
```

风险那一行是硬的。写不出风险的自荐是推销，不是建议。
agent 给出自荐但不替你决定；人回答后写进 `DECISIONS.md`。

## 8. 待你回答：恰好一个问题

- **恰好一个。** 两个问题等于没有优先级，会把决策成本还给已经被过载的人。
- **选项互斥**，2–4 个，标出推荐项并给每个选项一句代价说明。
- 问题必须是**闭环的**：回答完之后，下一步动作就确定了，不需要再澄清。

## 失败模式

| 症状 | 诊断 | 修法 |
|---|---|---|
| 摘要卡越写越长 | 没有区分"记录"与"接口" | 细节推回记录包，卡只留判断 |
| 结论全是 `薄` | 没有复现动作 | 下一块加复现，或降级为勘察 |
| "机制"全填实现问题 | 没在追问方法性质 | 至少给出一条候选方法性质 |
| 意外栏永远写"无" | 监控没接线或覆盖太窄 | 写明覆盖范围，扩大检查面 |
| 结尾三个问题 | 把决策成本转嫁给人 | 排序，只留最靠前的那个 |
| 结论与"绝不能声称"冲突 | 预注册被事后绕过 | 按"绝不能声称"改写结论 |
| 人读完仍不知道下一步 | 卡失败 | 重写"决策卡"和"待你回答"两栏 |
