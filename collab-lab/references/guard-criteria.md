# 目标守卫到底查什么（判据 1–8 详版）

> 从 `SKILL.md` 下沉到这里（第 38 轮）。SKILL.md 里只留"它查哪几类事实"的一句话索引。
> 什么时候读本文件：**守卫报了 FAIL/WARN/INFO 而你不确定它凭什么这么判**时；
> 或**要给守卫加一条判据**时。

跑法：

```bash
python scripts/goal_guard.py \
  --charter CHARTER.md --ledgers ledgers/ \
  --protocols protocols/ runs/ --decisions DECISIONS.md \
  --theory-ledger ledgers/theory-<topic>.md
```

**这是治"跑着跑着就偏了"的唯一运行时机制，不能按"每 2–3 块"的节奏省。**
退出码：`0` = 没偏离；`2` = 偏离已确认（先回 `CHARTER.md` 第 0 节说明下一步推进哪个目的，
再开新块）；`1` = 有 WARN。

它机械报出下列事实：

1. **每个目的有几条台账条目**（配比）。
2. **`method`/`bridge` 的最近入账之后又过了几个块**（超阈值 ⇒ FAIL）。
3. **理论闭环**：`成熟度=具体方向` 的 T- 条目**有没有实验出口**
   （协议块与台账的 `被用于` 必须**双向一致**，单向不算链接）。
4. **证伪条件待核对**：某条 T- 的实验出口已运行，而理论台账在此之后**未被修订**
   ⇒ 报 INFO 提示回头确认"证伪条件是否已被触发"。
   ⚠️ **它不判定"是否真的被触发"**（那需要语义理解）——它只给出一个可靠的机械代理信号。
   **立此检查的实测原因**：某条 T- 曾被它自己的证伪条件触发，但条目又挂了一轮没动，
   证据已否掉条目而条目未动，**全靠人碰巧回头看才发现**。
5. **挂起到期 / 降级去向**：理论台账的 `可用性` 只有三种取值，两种"不能用"都必须可核对。
   `挂起（到期 P-n）`：已存在编号 ≥ n 的协议块而该条仍写着 `挂起` ⇒ **FAIL**；
   `挂起` 没写到期块 ⇒ **FAIL**。`已降级（→ M-nn）` 没写去向 ⇒ **FAIL**。
   ⚠️ **到期块的编号要能写完整块名**（`挂起（到期 P-BOILER-021）` 与 `到期 P-021` 同等有效）——
   实测教训（`LESSONS-general` B44）：正则原先只认短名，于是**写得完全正确**的一条挂起
   被报成"没有到期日"，而最省事的"修法"是把它改成 `P-021`，那样到期日就指向一个**不存在的块**。
   ⇒ **误报最坏的地方不是多跑一次，是逼人把合规的写法改坏。**
   **立此检查的实测原因**：原有的三条降级判据是**入场**判据，它们**一条都不命中**
   一种更隐蔽的形态 —— 条目自己写着"**本条结论不可用**"然后无限期留在台账里。
   那是"永久免于证伪"，即 Lakatos 说的**退化的问题转换**。
   ⇒ 判据见 [theory-ladder.md](./theory-ladder.md)「降级判据」第 4 条：
   **挂起是允许的（它是保护带），没有到期日的挂起不是**。
6. **悬空理论引用**：某个协议块写着"本块服务于 `T-x`"，而理论台账里**没有 `T-x`**
   ⇒ **FAIL**。这是判据 3 的**反方向**（3 只管 T→块，块→T 此前无人看）。
   **立此判据的实测原因**：某条 T- 降级时若直接删掉它的标题，
   声明服务于它的三个协议块就**静默悬空**了 —— 而当时没有任何检查会报。
   ⇒ 它把"降级时保留标题 + 写去向"从一条好习惯变成了**机械要求**。
6b. **事后归因的理论链接**（`理论条目: T-x`（**事后归因**））⇒ 不算 FAIL，但**印成 INFO**。
   治的形态：块**跑完才逼出**理论条目（实测：`P-BOILER-018` 的一个反直觉读数逼出了
   `T-3`，而 `T-3` 写在块之后 ⇒ 块里不可能事前声明）。此前机制只有两种结局：
   **FAIL**（把链接从台账里删掉，等于隐藏一条真实的证据依赖）或**静默通过**
   （等于把事后归因冒充成事前声明）—— 两种都丢信息。
   ⇒ 第三种：**允许声明，但要求标明它是事后归因**，并让它出现在守卫输出里。
   标记必须落在**声明 T- 的那一行**上（正文里提一句不算，fixtures 里有对抗场景专门守这条），
   否则"标记"会变成一个可以随手贴上的豁免开关。
   ⇒ 人读守卫输出时能一眼看到"**哪些理论链接不是事前预注册的**"。
7. **哪些条目没打 `[goal]` 标记**（无法参与对账）。
8. **人面（`CHARTER` 的 `<headline>`）必须"新"且"短"**：
   ① 没提到**最新的协议块编号** ⇒ **FAIL**；② 超过 **700 字** ⇒ **FAIL**。
   **立此判据的实测原因**：`status.py` 每轮把 `<headline>` 印在一屏顶部，
   而此前**没有任何东西检查它是不是过时的** —— 实测它停在第 27 轮，
   而第 28/29 轮已经换掉了头号结论的支持链、还新开了一条理论条目。
   这正是本 skill 立文的症状：**人读到的"现在在哪"落后于实际进展**。
   ① 的合理性：它不判定措辞好不好，只强制"写这段话的人**看过**最新那个块"
   （与判据 4 用 mtime 做代理同一思路）。
   ② 的必要性：**行数预算可以被一整段话绕过** —— 一段 2000 字只算 1 行，预算照样通过，
   而人读不下去。⇒ 一屏的预算必须**同时管行数与单段长度**。
   配套：`status.py` 印 headline 时去掉 `**`（控制台不渲染，只会变成噪声）。

**代价是每轮一条命令；收益是偏离会被看见**，而不是等人中途打断。
