# 节奏与验收：闸门强度、五分钟测试、破例

## 1. 五分钟测试（最重要的验收标准）

**做法**：只读摘要卡的头两行（结论）和最后四行（决策卡 + 待你回答），合上文件，回答：

1. 发生了什么？
2. 下一步选什么？

**判据**：两分钟内能答完 → 通过。需要回读正文才能答 → **这张卡失败**，
不是读者的注意力问题，是卡的提炼失败，重写。

**为什么要这么测**：这套流程的唯一服务对象是"状态不好时还能不能推进课题"。
状态好的时候什么格式都能读；状态差的时候只有头尾能被读进去。所以头尾必须
自洽——它们不依赖正文的任何信息。

一个推论，写给 agent：**结论和选项不允许依赖正文才能理解。** 正文是证据，
头尾是判断。判断必须独立成立。

## 2. 闸门强度：严格（默认）

- **一个闸门 = 一个协议块。** 跑完必须等回答。
- **批准前不写消耗算力的代码。**
- **不许在等待期间"顺手"跑点别的。** 这条针对的是 agent 最常见的越界：
  等待被感知为闲置，于是自我填充。等待是流程的一部分，不是闲置。
- 人回答后立刻记 `DECISIONS.md`，然后回到起草下一个协议块。

### 为什么是严格而不是中度

过载的成因是"每一步都产生需要被重新解释的东西"。中度闸门允许块内自由跑变体，
块内就会产生你没来得及消化的中间结果——正是当前抗拒的来源。所以默认严格。

严格不等于慢：严格闸门让**每个块都必然产出可决策的东西**，块数少但每块有用。

## 3. 破例：唯一允许放宽的方式

**只允许由人主动放宽，agent 不得自行放宽。**

| 放宽方式 | 何时合理 | 代价 |
|---|---|---|
| "这个块内随便跑变体" | 方向已定，正在调参/消融 | 中间结果变多，需要人自己扛住不看 |
| "连跑两个块" | 人有一段完整时间跟读 | 第二个块的预注册质量会下降 |
| "这轮不用出摘要卡" | 纯勘察，读数字就够 | 勘察结论容易过拟合到印象 |

放宽必须口头明确并记进 `DECISIONS.md`。**默认永远回到严格。**

## 4. 什么时候该停下整个课题（而不是继续跑）

出现下面任一情况，**不要开下一个协议块**，先回到步骤 0 重读 `CHARTER.md`：

- 连续 3 个块的主指标变化都小于最小可检测效应 → 当前方向在噪声里，需要换判据或换问题；
- 连续 3 个块都在推同一个"堵点"的同一批原因 → 排查方式有问题，不是问题太难；
- 方法台账连续 3 条"被用于：无" → 累积的判断没有参与决策，流程在空转；
- **你自己开始不想看摘要卡了** → 这是最早的、也是最可信的失效信号。它说明卡的
  信息密度仍然过高，或者决策卡一直在给你不能决定的选择。停下来改格式，不是改课题。

最后一条值得单独说：抗拒不是懒惰，是接口失配的信号。**把它当成测量值，不是当成态度。**

## 5. Agent 自检（每个闸门结束时）

在交摘要卡之前，agent 自己过一遍：

1. 主指标是否按预注册口径算的（不是换了更好的那个）？
2. 摘要卡里的每个数字，能不能指出它来自记录包的哪个文件？
3. 结论的强度标签是否有依据？这个 session 是不是每次都填同一个标签？
4. "意外"栏写"无"了吗？写了覆盖面吗？
5. "机制"栏有没有至少一条在追问方法性质？
6. 验证覆盖：声明完成之前，点名**没有检查**的那一处。
7. 结尾是不是恰好一个问题，选项互斥？

任一条不过，先修再交。**把未验证的东西交出去，等于把判断成本转嫁给人，
而人正是这个流程要保护的那个瓶颈。**
