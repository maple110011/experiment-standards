# 协议块：判据先于结果

> **模板**: `assets/templates/PROTOCOL.template.md`

## 为什么必须先写

一个实验如果跑完才决定"它说明了什么"，那么每个结果都会开启一次新的开放式解释。
解释成本没有上限，而人的解释预算有——这是"信息过载"最容易被忽略的来源。

预注册把解释成本从"每个结果一次"降到"每个块一次"。代价是你必须在跑之前想清楚
要检验什么。这个代价是这套流程里最有价值的一笔支出。

## 一个协议块 = 一个问题

不是"跑一下 X 看看"，而是"检验命题 P"。判断标准：写完之后，你能不能说出
**什么结果会让你放弃 P**。说不出来，说明这还是个探索而不是一个块——那就先降到
"勘察"，勘察也有协议块，但它的主指标是"发现了什么此前不知道的事实"。

## 字段与要求

| 字段 | 要求 | 常见失败 |
|---|---|---|
| **块号** | `P-<topic缩写>-<序号>`，永不重用 | 用日期当块号，无法引用 |
| **一句话主张** | 本块检验的单一命题，≤40 字 | 塞进两个命题 |
| **为什么是这一步** | 它改变哪个决策 | "因为好奇" |
| **既有证据** | 引用台账条目编号 + 证据等级 | 重测已知结论 |
| **主指标** | **一个**，给公式/口径（不是名字） | 主指标三个，事后挑好的那个 |
| **最小可检测效应** | 来自 `score_noise_floor.py` 的数字 | 写"有提升" |
| **对照** | 至少一个，且与实验组只差一处 | 对照与实验组差三处 |
| **成功判据** | 预先写死的数值 | "效果变好" |
| **失败判据** | 同样预先写死 | 缺失 |
| **绝不能声称** | 本块的证据**不足以支持**的结论 | 缺失（最重要的一栏） |
| **停止规则** | 什么情况下提前停（时间/发散/无信号） | 缺失 |
| **预期成本** | 预计耗时、显存、算力；1-epoch 基准结论 | 未测基准就承诺 |

### 关于"主指标只有一个"

多指标可以记录，但**必须事先指定哪一个决定成败**。这不是学术洁癖：当你有 5 个指标、
10 个方法、若干超参时，"总有一个看起来变好了"是必然事件，它和真实改进无法区分。
预先指定主指标是把多重比较的代价控制住的唯一便宜手段。

### 关于"最小可检测效应"

摘要卡要报不确定度，这个数字就是它的来源。对榜单类任务用：

```bash
python scripts/score_noise_floor.py --n-test <测试集规模> --formula <公式> --tau <τ> --k <k>
```

**最小可检测效应同时约束成功判据**：成功判据的数值必须高于 MDE 所要求的门槛。
如果 MDE 说"0.70 与 0.70 无法区分"，那么成功判据写成 `≥ 0.70` 就是自相矛盾的——
通过与否在统计上不可区分。这条是最容易在自己最熟悉的例子上失守的一条规则
（本仓库的样张初版就犯过，见 `assets/samples/PROTOCOL-sample-001.md` 的修订痕迹）。

还要单独算一件事：**测试集里正类的数量**。它决定了 recall 的分辨率 `1/P`，
以及评测本身有多"脆"（一个预测翻转造成多少分数抖动）。正类数未知时给出扫描区间，
并明确写出"这是未知量"。带 `?` 的未知量不得在下游当已知用。

### 关于"绝不能声称"

这是最容易被跳过、也最有用的一栏。示例：

- 在单一数据切分上赢了 → 不能声称"方法更好"，只能说"这个切分上不劣"；
- 用测试集调了阈值 → 不能声称该阈值在新数据上有效；
- 改进小于最小可检测效应 → 不能声称有改进，只能声称"未观察到退化"；
- 只在 1 个任务上验证 → 不能声称"适用边界"，只能说"该任务上成立"。

写这一栏的作用不是自我审查，是**提前把后面可能出现的过度解读钉死**。有了它，
摘要卡才有资格把一个小效应如实写成 `薄`。

## 破例条件（唯一一条）

**同一协议块内**允许自由跑变体、消融、多种子——这是"中度闸门"，不需要每次回来问。
跨块必须等确认。破例的前提是：变体不改变主指标和成功判据。

这条破例存在的原因是：探索本身有价值，全部打断会让人机协作变成审批流程。
但它不延伸到跨块——跨块意味着方向选择，方向必须有人的判断。
