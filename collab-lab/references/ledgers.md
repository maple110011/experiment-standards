# 三级台账：问题台账、方法台账与理论台账

> **模板**: `assets/templates/LEDGER-problem.template.md`、`LEDGER-methods.template.md`、`LEDGER-theory.template.md`
> 理论台账的生成方法（七级梯子、触发条件）另见 [theory-ladder.md](./theory-ladder.md)

台账不是日志。日志记"发生了什么"，台账记"**我现在相信什么、凭什么**"。

日志可以无限长，台账必须短——因为台账要被人反复重读，而重读的成本决定它会不会
被真的重读。一个没人看的台账比没有台账更糟：它看起来像状态。

## 1. 为什么是三个，不是一个

| 台账 | 回答的问题 | 沉淀什么 | 对应你说的目的 |
|---|---|---|---|
| **问题台账** | 这个实际问题到底长什么样 | 数据怪癖、泄漏陷阱、评测噪声下界、域知识疑问 | 解决实际问题 |
| **方法台账** | 这个方法/这类方法到底怎么回事 | 陷阱、失效模式、适用边界、改进方向、关键问题 | 抽取方法洞见 |
| **理论台账** | 实践需要什么、方法给不了什么，而现有框架解释不了为什么 | 现象、张力、理论问题、两条竞争方向 | **从实际问题里生发可探索的理论问题** |

**混在一起的代价**：问题台账会淹没在方法细节里，方法台账会被具体领域的特例污染。
分开之后，方法台账才有资格被带到下一个课题去——这也是"方法探索"能跨竞赛复用的前提。

**为什么还需要第三个**：前两个都停在"观察"上。方法台账的条目必须是**可证伪的主张**，
而"这个方法缺了一块、文献里也没有"恰恰不是主张——它没有答案。它在方法台账里没有位置，
在问题台账里更没有。缺了这个位置，它只会在协议块结束时被写成一行"开放问题"，
然后随协议块一起消失。理论台账就是给这类东西一个**允许暂无答案**的去处。

三条机械规则帮你决定一条东西该进哪个台账：

1. 能写成"在条件 C 下，方法 M 表现为 P" → 方法台账（可证伪）；
2. 只能写成"在数据 D 上观察到 Q" → 问题台账；
3. 只能写成"需要 X，而方法给的是 Y，且现有框架说不了为什么" → 理论台账。

## 2. 证据等级

**四个标签，含义固定，不许自创。** 每条台账条目必须带一个。

| 等级 | 含义 | 允许的说法 |
|---|---|---|
| `稳定` | ≥2 次独立复现（不同切分/任务/种子），且通过了对照 | "在此条件下成立" |
| `薄` | 单次运行，或效应小于最小可检测效应 | "观察到，未验证" |
| `不稳` | 复现之间结论矛盾 | "矛盾，未定"（必须写清矛盾位置） |
| `?` | 推测，来自文献/推理，本课题无证据 | "我们猜" |

**`?` 不得作为下游前提。** 这是硬规则：一个未标记的猜测比"我不知道"危险得多，
因为它在后续步骤里会被当成已知事实使用。

## 3. "被用于"字段：台账的存活测试

每条台账条目必须有一个 `被用于` 字段，指向**具体的协议块编号**。

- 一条结论如果从未改变过任何一个协议块，它就没有在参与研究，只是在存档；
- 维护规则：**每 3 条结论里至少 1 条**要有非空的 `被用于`；
- 检查方式：全是"被用于：无"的台账，删掉重写；这不是纪律问题，是这份台账
  没有产出判断，只产出了措辞。

这个字段之所以是硬的，是因为它是唯一能区分"我们在积累理解"和"我们在生成文本"
的机械判据。

## 4. 问题台账条目格式

```
### Q-<序号> <一句话标题>
证据:    <文件/行数/命令输出>      等级: 稳定|薄|不稳|?
事实:    <观察到的是什么，用数字，不用形容词>
影响:    <它改掉了后面的哪个设计选择>
张力:    <可选：这里需要什么、方法/数据只能给什么，带数字>
被用于:  P-<块号> | 无
什么能改: <什么新证据会推翻或修正这条>
```

问题台账的价值集中在 `影响` 那一行长。一条不影响任何设计选择的事实，是百科条目，
不是台账条目——它应该留在勘察脚本的输出里。

`张力` 是可选字段，但**它是理论台账的主要矿源**：当一条问题条目的"需要 vs 能给"
落差开始反复出现、且排除不掉时，它就该沿 [theory-ladder.md](./theory-ladder.md)
往上爬。发现落差的时候就顺手写下来，比事后回想便宜得多。

## 5. 方法台账条目格式

```
### M-<序号> <一句话主张>
等级:     稳定|薄|不稳|?
主张:     <必须是一个命题，不是一次观察>
适用边界: <在什么条件下成立；什么条件下不成立>
复现:     <次数 + 独立来源（切分/任务/种子）>
被用于:   P-<块号> | 无
推翻条件: <什么实验会证伪它>       ← 空则不得升格为条目
改进方向: <如果这条成立，下一步可以试什么>（可选）
```

### 主张 vs 观察

| 观察（不合格） | 主张（合格） |
|---|---|
| SWAG 效果不好 | SWAG 在 n<500 时后验方差被系统性低估，导致 coverage95 < 0.85 |
| 不确定性没用 | 单切片 96h 窗口内，模型间不确定度与故障标签的 AUC 仅 0.55，低于可用的门控阈值 |
| MC Dropout 要训久 | MC Dropout 在少样本下需要 ≥3× 训练预算才能达到 Ensemble 的 ECE，预算不足时校准更差 |

区分方法：**把领域名词换成占位符，主张还成立吗？** 成立 → 方法洞见，可跨课题；
不成立 → 领域观察，应留在问题台账。

## 6. 理论台账条目格式

完整字段、成熟度分级与生成方法见 [theory-ladder.md](./theory-ladder.md)。要点：

```
## T-<序号> <一句话标题>
现象:      <哪个课题、什么条件下、观察到什么；不出现本题专有名词>
证据:      <等级> <来源 Q-/M- 条目 → run 目录>
缺口:      <实践需要什么 vs 方法能提供什么>
张力:      <精确落差，必须含数字>
现成解释不够: <试过的 2 条现成解释，为什么各自不够>
理论问题:  <"为什么 X 在 Y 下失效"或"在 Z 条件下正确的对象是什么">
成熟度:    初步观察 | 可研究的问题 | 具体方向
可用性:    可用 | 挂起（到期 P-<块号>）| 已降级（→ M-<号>）
方向A/方向B: <两条给出不同答案的路线>
区分实验:  <什么最小实验能区分 A 与 B>
被用于:    P-<块号> | 无
什么能证伪: <什么结果会让这条理论问题消失（即它其实是工程问题）>
什么能回答: <至少 3 个可能回答它的方向>
```

四条与其它台账不同的规则：

1. **允许暂无答案**（`被用于: 无` 常见且正当），但**必须挂在 Q-/M- 证据上**，不许空想；
2. **`张力` 里必须有数字**。张力是"需要 vs 能给"的落差，没有数字就只是印象，
   校验器会直接拒收；
3. **`理论问题` 里不许出现"怎么/如何让"**。那是工程问题的句式，说明提炼还没走完
   （第 6 级未到）；
4. **`可用性` 是唯一允许"暂时/已经不能用"的字段，两条都硬性可查**：
   `挂起（到期 P-011）` 必须带到期块（**没有到期日的挂起 = 永久免于证伪**，
   Lakatos 的"退化的问题转换"），到了 `P-n` 那一块还没处置守卫直接 FAIL；
   `已降级（→ M-11）` 必须写去向，且**标题要留在原位置**
   （删标题会让声明服务于它的协议块变成**悬空引用**）。
   见 [theory-ladder.md](./theory-ladder.md)「降级判据」第 4 条。

## 7. 洞见升格的门槛（两层不同，不要混用）

**进方法台账**（可证伪类），四条全满足：

1. 是一个**主张**（可被反驳）；
2. 带**适用边界**；
3. 有 **≥2 次独立复现**（否则一律 `薄`）；
4. 写得出**推翻条件**。

**进理论台账**（求问类，允许暂无答案），四条全满足：

1. **有实测的缺口**：张力含数字，且落差大于评测噪声下界；
2. **完成机械排除**：换过实现、超参/预算、种子、切分，落差仍在；
3. **完成全称化**：能用方法学语言陈述，并指出至少一处不相关任务上的同构现象；
4. **`理论问题` 里没有"怎么/如何让"**，且写得出"什么能证伪这条理论问题"。

写不满的先留在摘要卡的"机制"字段当候选。**不要为了填台账而降格门槛**——
门槛降低的那一刻，台账就从判断记录退化成了措辞收藏。

## 8. 跨课题的复用

两个台账的最终用途都是跨课题，但**合并方式不同**：

- **方法台账按课题计数**：主张里不要出现本题专有名词，跨课题复现时追加课题名，
  等级从 `薄` 升到 `稳定`。复现两次以上跨课题的条目是整个协作过程最有价值的产物。
- **理论台账按问题合并**：同一个理论问题在第二个课题上出现时，**不新开条目**，
  而是把课题名追加进去、成熟度升一级。理论问题跨课题出现，是它确实是理论问题
  （而非本题怪事）的最强证据。

## 失败模式

| 症状 | 诊断 | 修法 |
|---|---|---|
| 台账越来越长 | 把它当日志写 | 拆出日志文件，台账只留判断 |
| 全是 `薄` 且无复现 | 流程空转 | 下一块专门做复现 |
| `被用于` 全空 | 装饰品 | 删掉重写，或让结论真的影响下一块 |
| 条目里全是本题名词 | 领域观察混入 | 换成方法学描述，或移入问题台账 |
| 推翻条件写"更多实验" | 无法证伪 | 写出具体实验和具体判据 |
| `?` 出现在下游前提里 | 违反硬规则 | 立即标注或补证据 |
| 理论台账长期为空 | 缺触发条件，或第 2 级排除没做完 | 用理论梯子的触发条件检查一遍 |
| 理论问题写成"怎么…" | 工程问题伪装 | 改写成"为什么…失效"，校验器会拒收 |
| 理论台账条目互不相关且永不指向实验 | 收藏而非研究 | 只保留能指向区分实验的 |
