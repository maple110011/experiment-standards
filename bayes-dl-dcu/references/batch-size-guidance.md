# batch size 与空间换时间

## 核心原则

1. **先测吞吐再定 batch**：不同模型/算子的显存-吞吐曲线不同；必须先跑
   `throughput_bench.py` 或 1-epoch 基准。
2. **空间换时间不总是免费**：大 batch 提高吞吐，但会改变收敛行为；通常需要
   lr 线性/平方根缩放。图像模型 batch 512 比 128 快 1.34-1.37x，但精度略降 0.5-1 点。
3. **2 的幂不是魔法**：在 270M MLP 上，512 vs 480、1024 vs 1088 吞吐差异很小；
   但 2 的幂在部分算子/内存对齐上有微小优势，建议优先测 2 的幂再微调。
4. **BDL 方法的 batch 敏感性不同**：
   - MAP / Deep Ensemble / VBLL：对 batch 相对稳健，配合 lr 缩放即可。
   - MC Dropout / SGHMC：小 batch 的梯度噪声是方法本身的一部分，盲目加大 batch
     会改变噪声结构，需要重调 dropout / 噪声温度。
   - SWAG：大 batch 需要更多 epochs 收集快照，否则协方差估计差。

| 512 | 54.5 | 9392 | 5.2 |

| 960 | 72.9 | 13176 | 5.2 |
| 1024 | 73.3 | 13975 | 5.2 |
| 1088 | 77.2 | 14102 | 5.2 |
| 2048 | 107.9 | 18974 | 5.2 |
| 4096 | 178.1 | 23001 | 5.2 |
| 8192 | 321.8 | 25460 | 6.2 |

### CIFAR-10 小 CNN (0.8M) MAP 20 epochs, Adam lr 1e-3
| batch | 96 | 128 | 192 | 256 | 384 | 512 | 768 | 1024 |
|---|---|---|---|---|---|---|---|---|
| acc | .815 | .809 | .729 | .772 | .806 | .812 | .812 | .826 |
| train_time_s | 77.9 | 62.5 | 52.2 | 46.2 | 42.6 | 40.0 | 40.1 | 38.5 |

- 时间随 batch 单调下降; 精度非单调, 192/256 差, 1024 最好。
- 固定 lr 下不能想当然; 扫描 batch 是每台卡/每个模型都要做的一步。

### 实际训练验证（270M MAP 20 epochs）
- batch 512: 1183s, RMSE 29.7
- batch 8192: 536s, RMSE 18.3 (更快且更好)

### VGG16-BN (CIFAR-10, MAP/MCD 40 epochs)
- batch 128: MAP 430s / acc 0.9224; MCD 432s / acc 0.9113
- batch 512: MAP 320s / acc 0.9168; MCD 315s / acc 0.9024
- 结论: 图像模型大 batch 提速明显, 精度略降; 建议 lr 微调。

## 建议

- 回归/表格大模型: 显存允许时直接上 4096-8192, 配合 lr 平方根缩放。
- 图像 CNN: batch 256-512 是甜点区; 再大收益递减且精度下降。
- SGMCMC/MC Dropout: 先固定小 batch 保持噪声, 再通过多卡并行提高吞吐。
